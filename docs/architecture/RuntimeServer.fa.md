# معماری Runtime Server

## پروژه: NP.SDK

---

# مقدمه

**Runtime Server** هسته ارتباطی (Communication Core) پروژه **NP.SDK** است.

هدف از طراحی این سرور، ایجاد بستری سبک، توسعه‌پذیر و مستقل از رابط کاربری است تا برنامه‌ها، افزونه‌ها و سرویس‌های مختلف بتوانند از طریق شبکه محلی یا سایر بسترهای ارتباطی با یکدیگر تبادل پیام انجام دهند.

Runtime Server یک برنامه کاربردی (Application) نیست، بلکه یک **زیرساخت (Infrastructure)** برای سایر برنامه‌ها است.

---

# اهداف پروژه

اهداف اصلی Runtime Server عبارت‌اند از:

* ایجاد یک سرور سبک و سریع
* پشتیبانی از چندین Client به صورت همزمان
* مدیریت نشست‌های کاربران (Sessions)
* مدیریت کاربران و سطوح دسترسی
* مدیریت فرمان‌ها (Commands)
* مدیریت ابزارها (Tools)
* ثبت رویدادها (Logging)
* قابلیت توسعه توسط Pluginها
* قابلیت استفاده در پروژه‌های مختلف

---

# فلسفه طراحی

Runtime Server نباید وابسته به هیچ رابط کاربری باشد.

به همین دلیل:

* نباید وابسته به WinForms باشد.
* نباید وابسته به WPF باشد.
* نباید وابسته به Android باشد.
* نباید وابسته به Visual Studio باشد.

تمام این برنامه‌ها صرفاً Clientهایی هستند که به Runtime Server متصل خواهند شد.

# مسئولیت‌های Runtime Server

Runtime Server مسئول انجام وظایف زیر است:

* پذیرش Clientها
* ایجاد Session
* اعتبارسنجی کاربران
* بررسی مجوزها
* دریافت Commandها
* ارسال پاسخ
* ثبت Log
* مدیریت Pluginها
* مدیریت ابزارهای نصب‌شده

# مسئولیت‌هایی که Runtime Server ندارد

Runtime Server نباید مسئول موارد زیر باشد:

* طراحی رابط کاربری

* نمایش MessageBox

# اصل طراحی

در Runtime Server تلاش می‌شود اصول زیر رعایت شوند:

* مسئولیت واحد (Single Responsibility)
* توسعه‌پذیری
* وابستگی کم بین کلاس‌ها
* استفاده از Interfaceها
* قابلیت تست
* قابلیت جایگزینی اجزاء

---

# Transport

Runtime Server به گونه‌ای طراحی می‌شود که در آینده بتواند از چندین روش ارتباطی پشتیبانی نماید.

نمونه‌هایی از Transportها:

* HTTP
* WebSocket
* Named Pipe
* TCP/IP

هر Transport تنها مسئول ارسال و دریافت داده است و از منطق داخلی Runtime Server اطلاعی ندارد.

---

# Session

هر Client پس از اتصال دارای یک Session خواهد بود.

Session اطلاعاتی مانند:

* شناسه نشست
* زمان اتصال
* آخرین فعالیت
* کاربر متصل
* وضعیت اتصال

را نگهداری خواهد کرد.

---

# User

هر کاربر دارای اطلاعاتی مانند:

* شناسه
* نام
* رمز عبور (در آینده به‌صورت امن)
* نقش
* مجوزها

خواهد بود.

---

# Command

تمام درخواست‌ها به Runtime Server در قالب Command ارسال می‌شوند.

هر Command شامل اطلاعاتی مانند:

* شناسه فرمان
* نام فرمان
* پارامترها
* فرستنده
* زمان ارسال

است.

---

# Logging

تمام رویدادهای مهم سیستم ثبت خواهند شد.

مانند:

* شروع سرور
* توقف سرور
* اتصال کاربران
* قطع ارتباط
* خطاها
* اجرای فرمان‌ها

---

# Plugin

Runtime Server باید به گونه‌ای طراحی شود که در آینده بتوان قابلیت‌های جدید را بدون تغییر هسته سیستم به آن اضافه نمود.

به همین دلیل Pluginها یکی از بخش‌های اصلی معماری خواهند بود.

---

# آینده پروژه

در نسخه‌های بعدی قابلیت‌های زیر به Runtime Server افزوده خواهد شد:

* مدیریت Pluginها
* ابزارهای هوش مصنوعی
* ارتباط با مرورگر
* ارتباط با Visual Studio

* همگام‌سازی بین چند Runtime
* مدیریت سرویس‌ها
* مانیتورینگ
* داشبورد مدیریتی

# نتیجه‌گیری

هدف Runtime Server ایجاد یک زیرساخت پایدار، ماژولار و قابل توسعه برای پروژه NP.SDK است.

تمام اجزاء سیستم باید به گونه‌ای طراحی شوند که در آینده بتوان بدون ایجاد تغییرات اساسی در هسته، قابلیت‌های جدید را به آن اضافه نمود.

این سند، نقطه شروع طراحی معماری Runtime Server است و در طول توسعه پروژه به‌صورت مستمر تکمیل و به‌روزرسانی خواهد شد.
